# MoE（Mixture of Experts）とは？

最近の大規模言語モデル（LLM）でよく耳にする **MoE（Mixture of Experts、混合エキスパート）** について調べたのでまとめてみた。

## MoE とは？

MoE とは、**複数の「エキスパート（専門家）」と呼ばれる小さなネットワークを用意し、入力ごとに一部だけを使い分ける**仕組みのこと。

「すべての問題を 1 人の万能な人が解く」のではなく、「分野ごとの専門家チームを用意し、質問に応じて担当者を選ぶ」イメージ。

## 基本の仕組み

MoE は大きく 2 つの要素で構成される。

1. **エキスパート（Experts）**
   - それぞれ独立した小さなニューラルネットワーク
   - 数個〜数百個と、モデルによって数はさまざま
2. **ゲート / ルーター（Gating / Router）**
   - 入力（トークン）ごとに「どのエキスパートに処理させるか」を決める振り分け役

```
                ┌─────────────┐
   入力トークン → │  ルーター    │ → 上位 N 個のエキスパートを選択
                └─────────────┘
                       │
       ┌───────┬───────┼───────┬───────┐
   Expert1  Expert2  Expert3  ...   ExpertN
       │                │
       └──── 選ばれたエキスパートだけ計算 ────┘
                       │
                    出力を統合
```

ポイントは、**全エキスパートを動かすのではなく、ルーターが選んだ上位数個だけを使う**こと（スパースな活性化）。

## なぜ MoE が注目されるのか？

### メリット

- **計算コストを抑えつつパラメータ数を増やせる**
  - モデル全体のパラメータ（総容量）は巨大でも、1 回の推論で使うのは一部だけ
  - 「総パラメータ数」は大きいが「実際に動く（アクティブな）パラメータ数」は小さい
- **性能とコストのバランスが良い**
  - 同じ計算量なら、密（Dense）なモデルより高い性能を出しやすい
- **専門性の分担**
  - エキスパートごとに得意分野を持てる（とされる）

### デメリット・課題

- **メモリ消費が大きい**
  - 使うのは一部でも、全エキスパートをメモリに載せておく必要がある
- **学習が難しい**
  - 特定のエキスパートにばかり処理が偏る「ロードバランスの問題」が起きやすい
- **実装・運用が複雑**
  - ルーティングや分散処理の仕組みが必要

## Dense モデルとの違い

| 観点 | Dense（密）モデル | MoE（疎）モデル |
| ---- | ----------------- | --------------- |
| 計算の使い方 | 全パラメータを毎回使う | 一部のエキスパートだけ使う |
| 総パラメータ数 | = アクティブパラメータ数 | アクティブ数 ≪ 総数 |
| 計算コスト | パラメータ数に比例して増大 | 大規模化してもコストを抑えやすい |
| メモリ | 必要分のみ | 全エキスパート分が必要 |

> 「総パラメータ数」と「推論時にアクティブなパラメータ数」を分けて考えるのが MoE 理解のカギ。

## 代表的な MoE 採用モデル

- Mixtral（Mistral AI）
- DeepSeek-V シリーズ
- Grok / Gemini など、近年の大規模モデルの一部

（密モデルか MoE かを公表していないモデルも多い）

## まとめ

- MoE は「複数の専門家ネットワークを必要なときだけ使う」アーキテクチャ
- **ルーターが入力ごとに使うエキスパートを選ぶ**のが核心
- 計算コストを抑えつつモデルを大規模化できるのが最大の利点
- 一方でメモリ消費や学習の難しさといった課題もある

「総パラメータ数が大きい＝重い」とは限らない、という視点が新しい学びだった。
