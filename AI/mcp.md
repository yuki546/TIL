# MCP（Model Context Protocol）とは？

生成 AI（LLM）と外部のツールやデータをつなぐための標準規格、**MCP（Model Context Protocol）** について調べたのでまとめてみた。

## MCP とは？

MCP は、**LLM（AI モデル）と外部のデータソースやツールを接続するためのオープンな標準プロトコル**。
Anthropic が 2024 年に提唱したもので、その後さまざまな AI ツールに採用が広がっている。

ざっくり言うと、**「AI と外部システムをつなぐための共通の差し込み口（USB-C みたいなもの）」** というイメージ。

## なぜ MCP が必要なのか？

LLM 単体は、学習済みの知識しか持っておらず、外の世界とやり取りできない。
そこで「ファイルを読む」「DB を検索する」「API を叩く」といった連携が必要になるが、これには課題があった。

### MCP がない場合の課題

- AI ツールごと・連携先ごとに、**個別の独自実装**が必要
- 連携先が増えるほど組み合わせが爆発する（M × N 問題）
- 実装方法がバラバラで再利用しにくい

### MCP がある場合

- **共通プロトコルに従えば、どの AI ともどの連携先ともつながる**
- 連携先（サーバー）を一度作れば、対応する複数の AI から使える
- M × N が **M + N** に減る

> 「それぞれの組み合わせごとにケーブルを自作する」状態から、「USB-C 規格に統一する」ようなイメージ。

## 基本の構成

MCP は大きく 3 つの登場人物で成り立っている。

| 役割 | 説明 |
| ---- | ---- |
| **ホスト（Host）** | AI を使うアプリ本体（例：AI チャットアプリ、エディタの拡張など） |
| **クライアント（Client）** | ホスト内にあり、サーバーと 1 対 1 で通信する仲介役 |
| **サーバー（Server）** | 外部のツールやデータを MCP の形式で公開する側（例：ファイル、DB、外部 API） |

```
┌─────────────── ホスト（AIアプリ） ───────────────┐
│                                                  │
│   LLM  ←→  MCP クライアント  ←→ ┐                 │
│                                │                 │
└────────────────────────────────┼─────────────────┘
                                 │ MCP（共通プロトコル）
                    ┌────────────┼────────────┐
              MCPサーバーA   MCPサーバーB   MCPサーバーC
              （ファイル）    （DB）        （外部API）
```

## MCP サーバーが提供できるもの

MCP サーバーは、主に以下のような機能を AI に提供できる。

- **Tools（ツール）**：AI が呼び出せる「操作」（例：検索する、ファイルを書く、API を叩く）
- **Resources（リソース）**：AI が参照できる「データ」（例：ファイルの中身、DB のレコード）
- **Prompts（プロンプト）**：再利用できる定型のプロンプトテンプレート

## 身近な例

- エディタ（VS Code など）の AI 拡張が、MCP サーバー経由でローカルのファイルや Git を操作する
- AI チャットが、MCP サーバー経由で社内のドキュメントや DB を検索する
- GitHub・Slack・各種 SaaS などが MCP サーバーを提供し、AI から操作できるようにする

## まとめ

- MCP は **AI と外部ツール／データをつなぐオープンな標準プロトコル**
- 連携の **M × N 問題を M + N に減らせる**のが最大のメリット
- **ホスト / クライアント / サーバー**の 3 構成で、サーバーは Tools・Resources・Prompts を提供する
- 「AI 版の USB-C」のような共通規格として、対応ツールが広がっている

LLM 単体ではなく、外部とつないで実際の作業をさせる「**AI エージェント**」を作るうえで重要な土台になる技術だと感じた。
